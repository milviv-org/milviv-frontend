# 0006. pnpm 11 через corepack

- Статус: Принято
- Дата: 2026-10-20

## Контекст

pnpm быстрее npm, экономит место и строже к зависимостям: нельзя случайно импортировать пакет, которого нет в `package.json`. Глобально pnpm не установлен, есть corepack из Node. Последний pnpm 12 сменил формат исполняемого файла, и corepack 0.31 из Node 22 его не запускает.

## Решение

- `"packageManager": "pnpm@11.28.6"` в `package.json`. Запуск: `corepack pnpm <команда>`, или `pnpm`, если включить `corepack enable`.
- Установочные скрипты зависимостей по умолчанию запрещены (защита от атак через цепочку поставок). Разрешены явно в `pnpm-workspace.yaml` → `allowBuilds`: `lefthook`, `unrs-resolver`.
- Git hooks вызывают инструменты из `node_modules/.bin`, чтобы не зависеть от наличия `pnpm` в PATH.

## Последствия

Переход на pnpm 12 — после обновления Node/corepack, отдельным ADR. Новая зависимость с установочным скриптом требует осознанного разрешения в `allowBuilds`.
