# 0009. Слои на нативных `<dialog>` и Popover API, без Reka UI

- Статус: Заменён 0010
- Дата: 2026-10-27

## Контекст

ADR 0004 допускает headless-библиотеку (Reka UI) для сложной доступности: dialog, drawer, меню, тултип. Самое трудное в них — фокус-ловушка, возврат фокуса, Esc, клик мимо, слой поверх всего и блокировка страницы. Браузеры, на которые мы рассчитаны (современные, `es2022`), умеют это сами.

## Решение

- **AppDialog, AppConfirm, AppDrawer** — нативный `<dialog>` + `showModal()`: фокус заперт и возвращается на триггер, страница инертна, слой верхний (без войны `z-index`). Общий композабл `shared/ui/lib/use-modal-dialog.ts` добавляет только анимацию закрытия (`data-state` → `transitionend` → `close()`) и синхронизацию с `v-model`. Появление — CSS `@starting-style`. Прокрутка страницы блокируется CSS: `html:has(dialog:modal)`.
- **AppDropdownMenu** — Popover API (`popover="auto"` + `popovertarget`): верхний слой, Esc, закрытие кликом мимо и возврат фокуса — нативные. Своё — позиция у триггера и клавиатура ↑/↓/Home/End.
- **AppTabs, AppSegmented** — свои по WAI-ARIA (tablist, radiogroup) с общим `roving-focus.ts`.
- **AppTooltip** — CSS (`:hover` с задержкой, `:has(:focus-visible)`), как в дизайн-системе.

## Последствия

- Ноль килобайт зависимостей; поведение доступности — у браузера, а не в нашем коде.
- Нужны браузеры с `<dialog>`, Popover API и `@starting-style` (Chrome/Edge 117+, Safari 17.5+, Firefox 129+). В более старых нет анимации появления, но всё работает.
- В Firefox меню закрывается без анимации (нет свойства `overlay`) — косметика.
- Тултип на CSS обрезается контейнером с `overflow: hidden`. Если это станет мешать — перевести на `popover="manual"`.
- Пересмотреть, если понадобятся combobox с поиском или сложный выбор даты (этап 9): там Reka UI может оказаться дешевле своего кода.
