# 0010. Reka UI для интерактивных примитивов

- Статус: Принято
- Дата: 2026-10-27
- Заменяет: 0009

## Контекст

ADR 0009 строил слои на нативных `<dialog>` и Popover API. Для ближайших этапов этого мало: выбор даты (этап 9), выбор проекта и цели из списка, меню внутри прокручиваемых контейнеров, тултипы, которые не обрезаются контейнером. Каждый такой примитив — своя логика клавиатуры, фокуса, ARIA и позиционирования, которую пришлось бы писать и тестировать самим (а Popover API в happy-dom не тестируется вообще). ADR 0004 допускает headless-библиотеку по согласованию — согласовано.

## Решение

- `reka-ui` (headless, наследник Radix Vue) — основа всех интерактивных компонентов `shared/ui`: Dialog, AlertDialog, Drawer, DropdownMenu, Tooltip, Tabs, RadioGroup, Checkbox, Switch, Select, Progress.
- Reka UI импортируется **только** в `src/shared/ui` (правило ESLint). Экраны работают с обёртками `App*`, поэтому замена библиотеки затронет один слой.
- Вид — полностью наш: классы `mv-*` (CONVENTIONS, 6.2), состояния — атрибуты Reka (`data-state`, `data-highlighted`, `data-side`).
- Появление и исчезновение слоёв — `@keyframes` по `data-state`: Reka держит элемент в DOM до конца анимации.
- `AppUiProvider` в `App.vue` задаёт общие настройки (задержка тултипов).

## Последствия

- Свой код доступности (`roving-focus.ts`, `use-modal-dialog.ts`, позиционирование меню, свайп drawer) удалён; тестируем только свою логику и связи.
- Select на мобильном — список Reka, а не системный. Дизайн-система рекомендовала нативный `<select>` — README компонента Select в дизайн-системе нужно поправить.
- Зависимость на годы: при ломающем мажоре Reka — ADR о миграции или замене.
