# 0001. Feature-Sliced Design с проверкой границ линтером

- Статус: Принято
- Дата: 2026-10-20

## Контекст

Приложение будут поддерживать и расширять годами. Без жёстких правил зависимостей модули со временем начинают импортировать друг друга как попало, и любое изменение задевает всё.

## Решение

Слои FSD: `app → pages → widgets → features → entities → shared`. Слой импортирует только нижележащие слои, слайс — только через свой `index.ts`. Слайсы одного слоя друг друга не импортируют. Единственное исключение — `import type` между сущностями через их `index.ts`.

Правила проверяет `eslint-plugin-boundaries` (`eslint.config.ts`, блок `app/architecture`), нарушение роняет CI. Связи между модулями без прямых импортов — через доменные события (ARCHITECTURE.md, 3.5).

## Последствия

- Новая функция добавляется новым слайсом, без правки существующих.
- Иногда приходится опускать общий код слоем ниже — это осознанная плата за отсутствие паутины.
- Методология описана публично (feature-sliced.design), её можно изучить без автора кода.
