# Соглашения о коде

Обязательны для `src/` и `scripts/`. Пометки: **[lint]** — проверяет ESLint, **[check]** — проверяет скрипт в `pnpm check`, **[hook]** — git hook. Остальное — ревью.

Архитектура и слои — [ARCHITECTURE.md](ARCHITECTURE.md). Зависимости — [LIBRARIES.md](LIBRARIES.md).

## 1. Именование

| Что                            | Правило                                    | Пример                                   |
| ------------------------------ | ------------------------------------------ | ---------------------------------------- |
| Папки, слайсы, файлы `.ts`     | kebab-case                                 | `task-form/`, `roving-focus.ts`          |
| Компонент                      | PascalCase, имя уникально во всём проекте  | `TaskCard.vue`                           |
| Компонент UI-kit (`shared/ui`) | префикс `App`                              | `AppButton.vue`                          |
| Композабл                      | файл и функция `useXxx`                    | `useControlAttrs.ts` → `useControlAttrs` |
| Pinia store                    | файл `xxx.store.ts`, функция `useXxxStore` | `theme.store.ts` → `useThemeStore`       |
| Тип, интерфейс, класс          | PascalCase, без префикса `I`               | `TaskFilters`                            |
| Константа-настройка            | UPPER_SNAKE_CASE                           | `SWIPE_CLOSE_PX`                         |
| Объект-перечисление            | PascalCase + `as const`, без `enum`        | `RouteName.Home`                         |
| Булево значение                | `is` / `has` / `can` / `should`            | `isOverdue`, `canComplete`               |
| Обработчик в компоненте        | `on` + событие                             | `onSubmit`, `onTriggerKeydown`           |
| Тест                           | рядом с файлом, `<имя>.test.ts`            | `theme.test.ts`                          |

## 2. TypeScript

- Никаких `any`; неизвестное — `unknown` с сужением. **[lint]**
- Типы импортируются через `import type` / `type` в импорте. **[lint]**
- Экспортируемые функции — с явным типом результата.
- ID сущностей — брендированные типы (`TaskId`), не `string`.
- `null` — «значения нет» в данных; `undefined` — «не передано» в параметрах и props.

## 3. TSDoc

### Где обязателен

1. Каждый экспорт модуля: функция, класс, тип, интерфейс, константа, композабл, store.
2. Каждый prop, emit и slot компонента — в объявлении типа (`defineProps<{ /** … */ size?: … }>()`): IDE показывает его при наведении в шаблоне.
3. Компонент целиком — блок `/** … */` первой строкой `<script setup>`.

### Что писать

- **Первое предложение — ЗАЧЕМ** это существует: какую задачу решает для вызывающего.
- **Дальше — ПОЧЕМУ так**: ограничение, неочевидное решение, отвергнутая альтернатива, ссылка на ADR или раздел документации (`@see`).
- Не пересказывать код и типы. «Возвращает строку» — запрещено, тип это уже говорит.
- `@param` / `@returns` — только когда имя и тип не объясняют смысл (единицы, диапазон, особые значения).
- `@example` — для публичного API `shared/` с неочевидным использованием.
- `//`-комментарий внутри кода — только «почему», над строкой, к которой относится.

```ts
/**
 * Доля выполнения для полосы прогресса.
 *
 * Сервер может прислать `done > total` (задачу вернули в работу после пересчёта),
 * поэтому значение ограничивается 0…1, а не доверяется как есть.
 *
 * @returns `0` при `total = 0`: у пустого проекта прогресса нет, а не 100 %.
 */
export function toFraction(done: number, total: number): number
```

## 4. Компоненты Vue

- `<script setup lang="ts">`, порядок блоков `script → template → style`. **[lint]**
- `defineProps` / `defineEmits` / `defineSlots` — с типами; v-model — `defineModel`. **[lint]**
- **Компонент = шаблон + связывание.** Ветвления, вычисления, разбор, форматирование, переходы состояний — в функции или классе в `.ts`, с unit-тестом (раздел 5). В компоненте допустимо: вызвать функцию, `computed` от одного значения, пробросить событие.
- Больше ~200 строк — разделить.
- Компоненты `shared/ui` не знают о домене.
- `reka-ui` импортируется только в `src/shared/ui`. Остальной код использует обёртки `App*`. **[lint]**
- Иконки — явный импорт `~icons/lucide/<name>`; размер — `--mv-icon-size` у родителя.
- Поле ввода: `defineOptions({ inheritAttrs: false })` + `useControlAttrs` — `class`/`style` на корень, остальное на контрол.
- Подписки, таймеры, наблюдатели — только VueUse (`useEventListener`, `useTimeoutFn`); ручной `addEventListener` запрещён. **[lint]**
- Даты — только `@/shared/lib/date`. **[lint]**

## 5. Логика и тесты

| Где живёт логика   | Когда                                     | Пример                                  |
| ------------------ | ----------------------------------------- | --------------------------------------- |
| Чистая функция     | по умолчанию                              | `resolveTheme(preference, prefersDark)` |
| Класс              | есть внутреннее состояние + поведение     | очередь toast с лимитом                 |
| Композабл `useXxx` | нужны реактивность или жизненный цикл Vue | тонкая обёртка над чистыми функциями    |

- Размещение: домен — `entities/<x>/model/*.rules.ts`, фича — `features/<x>/model/`, без домена — `shared/lib/` или рядом с компонентом UI-kit (`shared/ui/<c>/<c>.ts`).
- Тест обязателен для каждой экспортируемой функции и класса с логикой, для композаблов с логикой, для скриптов (`scripts/lib`).
- Компонентный тест — только на поведение самого компонента (связи `aria-*`, свои события), не на поведение Reka UI.
- `describe` — имя тестируемой единицы; `it` — утверждение о поведении по-русски: `it('мусор в хранилище считается системной темой')`.
- Снапшоты разметки целиком запрещены.

## 6. CSS

### 6.1 Общее

- Стиль компонента — только `<style scoped>`. Глобальные стили — только `src/shared/styles`.
- Цвета, тени, радиусы, длительности, кривые, z-index — только токены. Отступы — `--space-*`.
- Анимируются только `transform` и `opacity`. Каждый компонент сам отключает сдвиги при `prefers-reduced-motion: reduce`.
- Слои Reka UI (dialog, drawer, menu, tooltip, select) появляются и исчезают через `@keyframes` по `[data-state]`: Reka ждёт окончания анимации, а не transition.
- Медиазапросы по размеру — только именованные (ADR 0012): `@media (--mv-tablet-up | --mv-desktop-up | --mv-mobile | …)`, в блоке стилей — `@import '@/shared/styles/media.css'`. Числа в `@media` запрещены. **[check]**
- Mobile-first: база — мобильная раскладка, шире — `--mv-<точка>-up`; `--mv-mobile` — только для «только мобильный».
- В JS — `MediaQuery` и `Breakpoint` из `@/shared/config`, никогда числа: `useMediaQuery(MediaQuery.DesktopUp)`.
- Сгенерированные файлы (`tokens.css`, `media.css`, `media-queries.ts`) не правятся руками — только `design/tokens.json` + `pnpm tokens`. **[check]**
- Тёмная тема — `[data-theme='dark'] .mv-x`. `:global()` запрещён: он снимает scope со всего селектора.
- Запрещены: `!important`, селекторы по `id` и по тегу без класса, цвета литералами.

### 6.2 БЭМ: имена классов

**Каждый класс начинается с `mv-`.** **[check]**

| Сущность             | Шаблон                         | Пример                                     |
| -------------------- | ------------------------------ | ------------------------------------------ |
| Блок                 | `mv-<компонент>`               | `mv-button`, `mv-task-card`                |
| Элемент              | `mv-<блок>__<элемент>`         | `mv-button__content`, `mv-dialog__title`   |
| Модификатор блока    | `mv-<блок>--<модификатор>`     | `mv-button--primary`                       |
| Модификатор элемента | `mv-<блок>__<элемент>--<мод.>` | `mv-tabs__count--muted`                    |
| Утилита (глобальная) | `mv-<утилита>`                 | `mv-h1`, `mv-num`, `mv-sr-only`, `mv-icon` |

**Блок**

- Имя блока = имя компонента в kebab-case без префикса `App`: `AppButton` → `mv-button`, `AppDropdownMenu` → `mv-dropdown-menu`, `TaskCard` → `mv-task-card`, `DevUiPage` → `mv-dev-ui-page`.
- Один компонент — один блок. Исключение: варианты одного компонента с общим файлом стилей (`AppDialog` и `AppConfirm` → блок `mv-dialog`, стили в `dialog/dialog.css`).
- Дочерний компонент составного компонента — **элемент** родительского блока, а не новый блок: `AppMenuItem` → `mv-dropdown-menu__item`.

**Элемент**

- Один уровень: `mv-card__title`, не `mv-card__header__title`.
- Имя — по роли, не по виду: `__title`, `__body`, `__icon`, `__actions`. Нельзя: `__left`, `__big`, `__blue`.

**Модификатор** — из props компонента:

| Prop                                | Шаблон                | Пример                                       |
| ----------------------------------- | --------------------- | -------------------------------------------- |
| `variant` или `tone` (перечисление) | `--<значение>`        | `mv-button--danger`, `mv-badge--success`     |
| Любое другое перечисление           | `--<prop>-<значение>` | `mv-button--size-sm`, `mv-tooltip--side-top` |
| Булев prop                          | `--<prop>`            | `mv-button--block`, `mv-button--square`      |

- Модификатор всегда вместе с базовым классом: `class="mv-button mv-button--primary"`.

**Состояние** (меняется во время работы). Используется первый подходящий способ:

1. Псевдокласс: `:hover`, `:focus-visible`, `:active`, `:disabled`, `:checked`.
2. ARIA-атрибут: `[aria-invalid='true']`, `[aria-busy='true']`, `[aria-current='page']`, `[aria-expanded='true']`.
3. Атрибут Reka UI: `[data-state='open' | 'closed' | 'checked' | 'unchecked' | 'active' | 'inactive']`, `[data-highlighted]`, `[data-disabled]`, `[data-side='top']`, `[data-swiping]`.
4. Только если ничего не подходит — модификатор-состояние: `mv-progress--complete`.

Запрещены классы `is-*`, `has-*`, `js-*`. Элементы для JS ищутся через `ref` или `data-*`, не по классу.

**Взаимодействие блоков**

- **Микс:** родитель ставит класс своего элемента на корень дочернего компонента: `<AppIconButton class="mv-dialog__close">`. Через микс родитель задаёт только внешнюю геометрию: `margin`, позиция в grid/flex, ширина. Цвета и внутренности — никогда.
- Внутренности чужого блока не стилизуются. Настройка — через props или публичные CSS-переменные блока.
- `:deep()` — только для элементов **своего** блока, которые отрисованы в слоте другого компонента.

**CSS-переменные**

| Вид                           | Шаблон               | Пример                               |
| ----------------------------- | -------------------- | ------------------------------------ |
| Токен дизайн-системы          | имя из `tokens.json` | `--color-bg`, `--space-4`            |
| Переменная блока (публичная)  | `--mv-<блок>-<имя>`  | `--mv-icon-size`, `--mv-icon-stroke` |
| Переменная блока (внутренняя) | `--mv-<блок>-<имя>`  | `--mv-button-height`                 |

Публичные переменные блока описываются в TSDoc компонента.

**Полный пример**

```vue
<template>
  <button class="mv-button mv-button--primary mv-button--size-sm" :aria-busy="loading || undefined">
    <span class="mv-button__content"><slot /></span>
  </button>
</template>

<style scoped>
.mv-button {
  --mv-button-height: var(--control-md);
  height: var(--mv-button-height);
}
.mv-button--size-sm {
  --mv-button-height: var(--control-sm);
}
.mv-button:disabled {
  opacity: var(--opacity-disabled);
}
.mv-button[aria-busy='true'] .mv-button__content {
  visibility: hidden;
}
[data-theme='dark'] .mv-button--primary {
  /* … */
}
</style>
```

## 7. Доступность

- Интерактивные элементы — только из `shared/ui` (там доступность проверена).
- Кнопка без текста — `AppIconButton` с обязательным `label`.
- Цвет никогда не единственный носитель смысла: рядом иконка или слово.
- У каждого слоя (dialog, drawer) есть заголовок.

## 8. Зависимости

- Новый пакет → строка в [LIBRARIES.md](LIBRARIES.md) (зачем, почему он, цена, когда пересмотреть) в том же коммите.
- Архитектурный выбор (меняет подход, а не добавляет утилиту) → ADR в `docs/adr/`.
- Пакет с установочным скриптом → явное разрешение в `pnpm-workspace.yaml` (ADR 0006).
