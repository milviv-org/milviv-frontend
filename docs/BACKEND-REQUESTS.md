# Доработки бэкенда для фронтенда

Что нужно изменить в REST API (`skyrim_grade_java`), чтобы фронтенд работал так, как задуман в дизайне. Каждый пункт независим. Порядок — по важности.

| #   | Доработка                   | Без неё на фронте                                                                 |
| --- | --------------------------- | --------------------------------------------------------------------------------- |
| 1   | Префикс `/api`              | Не развести адреса страниц и API на одном домене без переписывания путей в прокси |
| 2   | `total` в списках           | Нельзя сделать нумерованную пагинацию                                             |
| 3   | Поиск `q` в `GET /tasks`    | Поле поиска скрыто флагом                                                         |
| 4   | `title` в истории баллов    | Название извлекается из английской строки `reason` — хрупко                       |
| 5   | `changes` в предложениях ИИ | Пользователь подтверждает изменения, не видя, что меняется                        |

---

## 1. Префикс `/api` для всех маршрутов

**Зачем.** Страницы фронтенда (`/tasks`, `/goals`, …) и маршруты API совпадают, а cookie (`SameSite=Strict`, `credentials: 'same-origin'`) требуют одного домена. Префикс разводит их: всё, что начинается с `/api`, nginx отдаёт бэкенду, остальное — фронтенду.

**Что сделать.**

- Все маршруты — под `/api`: `/api/auth/login`, `/api/tasks`, … (например, `server.servlet.context-path=/api`).
- Путь refresh-cookie — `/api/auth` вместо `/auth`. Access-cookie остаётся с `Path=/`.
- Обновить `docs/rest-api`.

**Проверка.** `POST /api/auth/refresh` получает refresh-cookie; `GET /tasks` (без префикса) бэкенд больше не обслуживает.

## 2. `total` в ответах списков

**Формат:**

```json
{ "items": [ … ], "total": 134 }
```

- `total` — сколько всего элементов с **теми же фильтрами** (`status`, `projectId`, `goalId`, `taskId`, `q`…), без учёта `limit` и `offset`.
- Нужен в: `GET /tasks`, `/projects`, `/goals`, `/plans`, `/rewards`, `/points/history`, `/reflection/answers`, `/ai/requests`, `/statistics/projects`, `/statistics/goals`.
- Не нужен (там жёсткий малый предел): `/reflection/questions`, `/ai/memories`, `/settings/sounds`.
- `GET /rewards` без верного пароля скрытых наград: скрытые в `total` **не входят** — иначе по числу видно, что они есть.

## 3. Поиск по задачам: параметр `q` в `GET /tasks`

- Подстрока без учёта регистра в `title` **или** `description`.
- Пробелы по краям обрезаются; пустая строка = параметра нет; длина 1–100, иначе `400 VALIDATION`, поле `q`.
- Сочетается с остальными фильтрами через «И»; `total` учитывает `q`.
- Порядок — как без поиска (новые первыми).
- Подсветку совпадения и фрагмент описания фронтенд строит сам из `description` — от бэкенда ничего не нужно.

После внедрения на фронте включается флаг `features.taskSearch`.

## 4. `title` в записях истории баллов

```json
{ "id": 41, "kind": "TASK_COMPLETED", "amount": 8, "title": "Выучить времена", "reason": "Task completed: Выучить времена", … }
```

- `title` — название задачи или награды **на момент события** (как сейчас в `reason`).
- `null` для скрытой награды — всегда, независимо от пароля (название скрытой в историю не пишется).
- Для старых записей — заполнить миграцией из `reason` или оставить `null` (фронтенд тогда покажет только вид операции).
- `reason` можно оставить для обратной совместимости.

## 5. `changes` в элементах `pendingApproval`

**Зачем.** Сейчас пункт подтверждения — «Изменить · Задача · Выучить времена Simple», без того, что именно изменится. Подсказку нельзя брать из текста ИИ — она обязана совпадать с тем, что реально выполнится.

```json
{
  "itemId": "u1",
  "op": "UPDATE",
  "type": "TASK",
  "title": "Времена группы Simple",
  "changes": [
    { "field": "deadline", "from": "2026-10-22", "to": "2026-10-29" },
    { "field": "difficulty", "from": "ADEPT", "to": "EXPERT" }
  ]
}
```

- Строится сервером из реальной операции: только поля, которые меняются.
- `field` — имя поля как в API (`title`, `description`, `difficulty`, `points`, `startDate`, `deadline`, `projectId`, `goalId`, `cost`).
- `from` / `to` — сырые значения API (даты `YYYY-MM-DD`, enum, числа, uuid). Русский текст («срок: 22 окт → 29 окт») и названия проекта или цели по `projectId`/`goalId` формирует фронтенд — так формат един по всему приложению.
- Для длинных текстов (`description`) — `from`/`to` = `null`, только факт изменения поля.
- У `DELETE` — `changes: []`.
